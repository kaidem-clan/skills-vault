# AGENTS.md — правила для агентов в этом репозитории

Этот репозиторий — хранилище скиллов и slash-команд. Следуйте правилам при любом изменении.

## Структура

```
skills/<source>/<skill-name>/SKILL.md   # один скилл = одна папка
commands/<source>/<command>.md          # одна команда = один .md файл
```

- `<source>` — короткое имя источника (автора/репозитория), например
  `emilkowalski`, `mengto`, `owl-listener`. Новые скиллы от известного
  источника кладите в его папку; новый источник — новая папка.
- Скилл хранит все свои файлы (скрипты, шаблоны, референсы) внутри своей папки.
- Команды — самостоятельные воркфлоу (`.md` с frontmatter `description`),
  они могут ссылаться на скиллы, но скиллы не должны зависеть от команд.

## Добавление нового скилла

1. Создайте папку `skills/<source>/<skill-name>/` с файлом `SKILL.md` внутри.
2. **Автоматически** добавьте строку в таблицу его секции в `README.md`:

   ```markdown
   | `skill-name` | Краткое описание в одну строку: что делает и когда применять. |
   ```

3. Новый источник — новая секция `###` в «Навигации по скиллам» со ссылкой
   на репозиторий, количеством скиллов и лицензией.

## Добавление новой команды

1. Положите `<command>.md` в `commands/<source>/`.
2. Добавьте строку `| /command-name | Описание. |` в «Навигацию по командам»
   в `README.md`.

## Синхронизация с README

README.md — это навигация. Скилл или команда, которых нет в README, считаются
не добавленными. Не оставляйте таблицы и фактическое содержимое репозитория
в рассинхроне:

- при переименовании или удалении — обновите/удалите строку в таблице;
- при изменении назначения — обновите описание;
- счётчики скиллов/команд в заголовках секций держите актуальными.

## Прочее

- Не храните в этом репозитории секреты, токены и ключи.
- Проверяйте лицензию источника перед импортом и указывайте её в README.
